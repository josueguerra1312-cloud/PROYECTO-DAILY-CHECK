# Contribución

1. Crea una rama desde `main`.
2. Mantén la lógica de negocio separada de la lectura y escritura de Excel.
3. Agrega pruebas para cada cambio de regla.
4. Ejecuta `pytest -q` y `ruff check .` antes de abrir un pull request.
5. No incluyas datos operacionales, matrículas reales adicionales ni archivos Excel.

## Convención de commits sugerida

- `feat:` nueva funcionalidad.
- `fix:` corrección.
- `test:` pruebas.
- `docs:` documentación.
- `refactor:` mejora interna sin cambiar resultados.
